## A4：其他 daemon 扫描 — ⚠️ 基本到位，但扫描方法有盲区（附 1 个低风险遗漏）

- 旧副本真改名了 ✅，scripts/ 下**没有**遗留的活动 token_dashboard_server.py ✅（活动版只在 projects/token-dashboard/ 跑）

### A4.2 basicConfig daemon 扫描 — ⚠️ 任务给的 glob 漏扫
- **CEO 任务里的扫描命令**：
  `grep -rl "logging.basicConfig" projects/*/src/**/*.py projects/*/*.py` → **空结果**（看似干净）
- **我用更严的全递归复核**：
  `grep -rl "logging.basicConfig" projects/ --include="*.py"` → **抓到 1 个被漏掉的文件**：
  ```
  projects/2026-06-14-录事-文字输入终端/02-代码/lushi_esp32_server.py
  ```
- **为什么原 glob 漏掉**：该文件在 `02-代码/` 子目录，既不在 `src/` 也不在项目根，原 glob 两个模式都匹配不到 → 会给出**假干净**结论。

### A4.3 对漏掉文件的风险定性 — 低风险（休眠，非同类灾难）
```
$ grep -n "logging.basicConfig" lushi_esp32_server.py   → 49 行有
$ grep -n "filename=" lushi_esp32_server.py             → 空（basicConfig 无文件 sink，只写 stderr）
$ grep -niE "app.run|serve_forever|while True|socket.|HTTPServer|Flask|uvicorn|run(" → 空（未见明显守护循环）
$ grep -cn "exc_info" lushi_esp32_server.py             → 1
$ ps aux | grep lushi_esp32_server.py                   → NOT RUNNING
$ crontab -l | grep lushi_esp32                         → not in crontab
$ ls ~/Library/LaunchAgents | grep lushi/esp32/录事     → no matching launchd plist
```
**结论**：本次爆盘灾难的成因 = launchd StdErrPath→文件 + basicConfig + exc_info 热路径 = 文件无限增长。该漏掉文件：
- basicConfig **无 filename=** → 只走 stderr，**没有持久文件 sink**
- **当前未运行**、**不在 crontab**、**不在任何 launchd plist** → 无自动拉起 + 无文件重定向
- 仅 1 处 exc_info、未见守护循环
→ **当前磁盘爆盘风险可忽略**，定性为休眠态卫生隐患，非同类灾难。

**A4 判定 ⚠️**：旧副本改名这条 ✅ 完成；但"扫描其他 daemon"这条**用的 glob 不完整、会漏报**。漏掉的 `lushi_esp32_server.py` 现在低风险（休眠/无文件 sink/无自启），**建议补一刀**：若以后要把它挂 launchd/cron，先把 basicConfig 改成 RotatingFileHandler 并去掉 exc_info，别让它变成下一个事故。
