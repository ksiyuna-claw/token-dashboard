# 员工卡怎样显示本人和分身的工作

2026 年 11 月 24 日，董事长确认保留“分身工作时，负责人也显示工作中”的原设计。这条规则同时适用于分身留在后台运行的本机程序。董事长需要借这块看板决定是否该去催人。

| 看到了什么 | 员工卡怎么显示 |
| --- | --- |
| 网关确认本人或同一角色的分身正在运行 | 该角色工作中，同一个分身只计一次 |
| 分身启动后台程序，能核对会话、程序实例和运行情况 | 该角色工作中，注明分身的后台程序；程序结束就移除这条依据 |
| 对焦虾独立审核 | 对焦虾按自己的运行情况显示。原单、负责人、实例和轮次一致，仍在等审核时，负责人显示等审核；如果负责人还有另外的活，它仍显示工作中 |
| 云端任务刚提交 | 显示已提交、等结果。已有记录明确说正在运行才显示工作中，结束记录会清除；状态太旧时显示待确认 |
| 刚打开、连接断开或某项工作无法核实 | 受影响的卡显示状态待确认。页面数据过期会标出，资料不足时总览不会声称全部空闲 |

## 为什么改

旧版用会话上次更新时间、短时间内收到事件，以及后台命令里出现的工作目录来推断工作状态。刚结束的会话可能继续亮灯，安静运行的长任务可能熄灯，共用目录也可能认错人。现在最后活动时间仍能查阅。判断当前工作时使用网关的活动名单、实际进程和原任务记录。

## 维护入口

- [活动名单和断线恢复](../../dashboard_activity.py)在订阅成功后读完整活动名单。日常接收开始、结束事件，也定期重新核对；分页读失败或断线时保留最后确认时间。
- [后台工作](../../dashboard_background.py)从角色自己的工具记录找出后台程序，按会话核对 OpenClaw 的程序登记。能查到本机进程身份时也可核对。云端读取 OpenClaw 原生图像、视频和音乐工具已写入会话的任务回执，以及现有可灵命令行工具可识别的回执。增加一种来源时，应有真实的任务身份、状态与结束依据。
- [审核等待和员工卡](../../dashboard_status.py)只读原任务。普通定时程序继续在系统任务栏展示。同一角色同时有多项工作时，已确认的工作优先显示。
- [页面](../../templates/token_dashboard.html)每 15 秒更新，标签页筛选仍保留员工的整体工作状态。模型用量和员工工作状态分别统计。
- [现场验收与还原](</Volumes/ZHITAI/codex_project/八爪鱼总裁办公室/Token看板工作状态维修-20261124/验收.md>)。历史记录保留在原位置。
