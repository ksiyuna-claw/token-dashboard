# ADR-0001: 状态判定优先级链

## 日期
2026-06-20

## 状态
已采纳

## 背景
看板需要判断每只虾是"工作中/等待中/空闲"，数据源有多个（Gateway hasActiveRun、exec进程检测、WS活动、session updatedAt），各有各的失效模式。单一数据源无法覆盖所有场景，需要组合使用。

## 决策
采用多层优先级链，从最精确信号到最粗粒度信号逐级降级。`/agent-status` 端点按以下顺序依次检查，命中即返回。

## 规则细节

| 优先级 | 条件 | 输出状态 |
|--------|------|----------|
| 1 | `hasActiveRun=True`（2分钟TTL内） | working |
| 2 | 有活跃exec进程 | working |
| 3 | WS 30秒内有事件 | working |
| 4 | `updatedAt` 90秒内 | working |
| 5 | `updatedAt` 90秒–10分钟 | waiting |
| 6 | `updatedAt` >10分钟 | idle |
| 7 | idle >30分钟 | stale |

## 决策人
匡书记

## 备注
- 优先级 1–3 是主动信号（虾确实在干活），优先级 4–7 是被动推断（根据最后活跃时间猜）
- TTL 和阈值经过实际观察调优，不要随意更改
